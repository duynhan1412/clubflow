# Campaigns — C1 and C3

Owner: Trịnh Duy Nhân.
Status: resource contract; handlers and UI are not implemented.
This document adopts the existing README routes. All bodies are JSON; unknown query parameters return 400 VALIDATION_FAILED (field path `query.<name>`). No endpoint here accepts query parameters. Path `campaignId` is a non-empty campaign ID; an unknown ID returns 404. Requests use relative /api URLs.

## Response schemas

Public collection: `{ campaigns: PublicCampaign[] }`. Public detail: `{ campaign: PublicCampaign }`. Executive detail and successful writes: `{ campaign: ExecutiveCampaign }`. All listed response properties are always present; no internal store, accounts, passwords, applications, screening notes, assignments or results are embedded.

| PublicCampaign field | Type and meaning |
| --- | --- |
| id | Non-empty string, immutable within the campaign. |
| name, hostClub, description, instructions | Non-empty strings for Published campaigns. |
| status | Literal Published on public endpoints. |
| opensOn, closesOn, interviewDate | Real calendar dates as YYYY-MM-DD. |
| timeZone | Literal Asia/Ho_Chi_Minh. |
| departments | Department array, schema below. |
| availabilitySlots | Array of { id: non-empty string, start: HH:mm, end: HH:mm }; campaign-local applicant input windows. |

ExecutiveCampaign contains every public field, with status Draft or Published, plus `interviewWindow: { start, end } | null`, `durationMinutes: 15 | 20 | 30`, and `roomIds: string[]`. Dates and interviewWindow may be null in an incomplete Draft; required text may be empty there. Availability slots are empty until interview setup is configured. The Executive shape is a configuration view, not permission to PATCH its server-owned properties.

Department: `{ id: string, name: string, positions: Position[] }`. Position: `{ id: string, title: string, quota: integer | null, description: string, requirements: string }`. Department IDs are unique within the campaign; position IDs are unique across all its departments. IDs are non-empty strings without surrounding whitespace. Referenced position IDs identify the same position across updates. Input text is stored as supplied; required-text checks use trimmed text. No additional text-length limits are imposed.

## Write fields and lifecycle

| Field | POST create | PATCH | Constraints/default |
| --- | --- | --- | --- |
| id | Required | Forbidden | Non-empty unique string; not generated by the server. |
| name, hostClub, description, instructions | Optional | Optional | Strings; omitted create fields default to empty strings. |
| opensOn, closesOn | Optional | Optional | YYYY-MM-DD or null; default null. |
| departments | Optional | Optional | Full replacement array; default []; no implicit merge of department/position rows. |

POST and PATCH accept only the fields in this table. Nested department/position objects accept exactly the documented properties; all are required when their row is supplied. Row text may be empty in Draft, but row IDs must be valid. Draft quota may be null or an integer (including a non-positive integer while editing); other types are refused. Empty PATCH is a successful no-op unless locked. Omitted PATCH fields remain unchanged. Null text or null arrays are invalid.

New campaigns always have status Draft, timeZone Asia/Ho_Chi_Minh, interviewDate null, interviewWindow null, durationMinutes 20, roomIds [] and availabilitySlots []. C4 owns interviewDate, interviewWindow, durationMinutes, roomIds and interviewer configuration. The status and timeZone are server-owned. Preview renders current form state locally and makes no additional API request.

Draft saves permit incomplete required fields and inconsistent date order, but non-null dates must be real calendar dates. Publish requires trimmed non-empty campaign text, opensOn <= closesOn < interviewDate, at least one department, and at least one position in each department. Each department needs a name; each position needs title, description, requirements and a positive integer quota. Publish errors use 400 VALIDATION_FAILED and zero-based paths such as `departments.0.positions.0.quota`; leave status Draft and the store unchanged. Interview configuration completeness beyond a valid interviewDate is not a C3 publication gate.

A Published campaign may be PATCHed before schedule confirmation, provided the resulting campaign meets the publication field requirements and its application period does not overlap any other Published campaign's period. Existing applications prevent removing/replacing referenced position IDs; return 409 REFERENCED_DATA_LOCKED with the affected applicationIds and fieldErrors. Availability is not writable through C3. Confirmation locks configuration writes to that campaign, including PATCH and publish.

Published campaigns retain their status, data and scoped access after applications close. A Draft may become Published when no other Published campaign is accepting applications on the campaign-local date and its own application period does not overlap another Published campaign's period, including closed and future periods. Both endpoints of each period are inclusive: a shared closing/opening date overlaps, and consecutive calendar days do not. Evaluate the current date in Asia/Ho_Chi_Minh (PA#3 uses MOCK_DATE, default 2026-11-06; PA#4 uses the server clock). The application-example date override does not apply here.

Return 409 ACTIVE_CAMPAIGN_EXISTS on first publication if another campaign is accepting applications or the application periods overlap, and on PATCH of a Published campaign if the resulting periods overlap. For an overlap, return fieldErrors at opensOn and closesOn; for a current-campaign blocker alone, use an empty fieldErrors object. Use an empty applicationIds array in both cases. Validate fields before checking these gates. Check the current Published campaigns and apply the write atomically so concurrent requests cannot create overlapping periods. On success, change only the requested campaign. Publishing an already Published campaign is idempotent (200, unchanged), unless its schedule is Confirmed, in which case the lock takes precedence.

## Shared errors and mock modes

All errors use the envelope in [README](README.md#error-shape); no refused write changes the store. Error messages below are examples; codes and field paths are contractual.

| Status | Code | When |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | Invalid JSON, unknown/read-only fields, wrong types or field constraints. Invalid JSON uses an empty fieldErrors object. |
| 401 | `UNAUTHENTICATED` | Missing/invalid Bearer token on an Executive endpoint. |
| 403 | `FORBIDDEN` | Valid token whose role is not Executive. |
| 404 | `CAMPAIGN_NOT_FOUND` | Unknown campaign; public detail also hides Draft campaigns. |
| 409 | `CAMPAIGN_ID_CONFLICT` | POST campaign ID already exists. |
| 409 | `ACTIVE_CAMPAIGN_EXISTS` | First publication while another campaign is accepting applications, or a first publication/Published edit with overlapping application periods. |
| 409 | `CAMPAIGN_LOCKED` | Campaign's schedule is Confirmed; any configuration write is refused. |
| 409 | `REFERENCED_DATA_LOCKED` | A write would remove/change identifiers or availability protected by existing references. |
| 500 | `MOCK_UNAVAILABLE` | Simulated error mode, using the README envelope. |

Normal and slow modes return the same schemas after about 150 ms and 2 seconds respectively. Error mode returns 500 without writing. Empty mode empties every JSON array recursively, keeps objects and scalar fields, and reports zero for list counts (these endpoints expose no count fields). Normal validation rules are not relaxed for writes in empty mode.

For protected routes authenticate and authorize before looking up the campaign. For writes, check the confirmation lock before body validation, then validate fields/references, then check publishing conflicts. Simulated error mode is applied by the runner first. Public endpoints do not require a token.
